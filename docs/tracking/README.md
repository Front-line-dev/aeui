# AEUI 작업 추적

`docs/tracking`은 현재 코드와 작업 상태를 기록한다. 이 폴더는 스펙이 아니며 [`docs/spec`](../spec/README.md)의 규칙을 추가하거나 변경하지 않는다.

| 문서 | 역할 |
|---|---|
| [알려진 구현 결함](known-defects.md) | 현재 코드가 현재 스펙을 위반하는 지점과 수정 상태 |
| [계획 기능](planned-features.md) | 아직 현재 스펙에 포함하지 않은 기능과 개선 계획 |
| [구현 및 검증 근거](implementation-evidence.md) | 현재 소스, 기존 테스트와 임시 검증에서 관찰한 스펙이 아닌 참고 자료 |

## 관리 규칙

1. 코드가 현재 스펙을 위반하면 스펙을 잘못된 코드에 맞추지 않고 `known-defects.md`에 등록한다.
2. 결함 문서는 잘못된 관찰 결과와 진행 상태를 기록하고, 올바른 동작은 `docs/spec`의 조항을 링크한다.
3. 아직 적용하지 않은 기능은 `planned-features.md`에서 관리한다. 계획 문서는 지금 반드시 구현해야 하는 동작이나 테스트 기대값이 아니다.
4. 계획 기능을 구현할 때는 확정된 계약을 먼저 `docs/spec`으로 옮긴 뒤 테스트와 코드를 같은 변경에서 구현한다.
5. 현재 소스나 기존 테스트를 조사한 내용은 `implementation-evidence.md`에 기록한다. 구현 변경으로 낡을 수 있으며 스펙보다 우선하지 않는다.
6. 완료된 결함과 계획은 추적 문서에서 제거하고, 필요한 설계 배경만 `docs/internals`에 남긴다.
